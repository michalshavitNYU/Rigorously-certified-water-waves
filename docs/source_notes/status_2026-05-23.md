### Known caveats / debts in the merged proofs

1. **`h_H_contdiff` hoist in `fft_hilbert_series_correct` (Area F).** The
   theorem takes `h_H_contdiff : ContDiff (M+1) (periodicHilbert G)` as
   a caller hypothesis. This is a real mathematical fact (the Hilbert
   transform preserves C^k smoothness on `2π`-periodic inputs) that
   Mathlib does not currently provide. Should be promoted to a lemma in
   a new `HilbertSmoothness.lean` so callers do not have to discharge
   it. Tracked as part of Phase 5 / G assembly.
2. **`h_derivs_acc` hoist in `fft_hilbert_series_correct`.** This is
   *not* a debt — it is the correct trust boundary per the architecture
   goal. It will be discharged by an atomic `cert_arb_fft_*` axiom once
   Phase 6 audit completes.
3. **Two `linter.style.longLine` warnings** on the 111-coefficient
   header in `Certificate.lean`. Cosmetic only.

### (b) Close the Hilbert-smoothness Mathlib gap

Promote the `h_H_contdiff` hoisted hypothesis in
`fft_hilbert_series_correct` to a proven lemma. Create
`HilbertSmoothness.lean`:

```
theorem hilbert_contDiff
    {k : ℕ} {G : ℝ → ℝ}
    (hG : ContDiff ℝ k G) (hG_per : Function.Periodic G (2 * Real.pi)) :
    ContDiff ℝ k (periodicHilbert G)
```

Proof sketch: H is a Fourier multiplier (`c_k ↦ -i sign(k) c_k`).
`ContDiff k` is equivalent to Fourier-coefficient decay `|c_k| ≤ C/|k|^k`;
the multiplier has unit magnitude, so decay is preserved.

This eliminates a caller burden but is **not** on the critical path
to deriving the residual axiom — can land after Phase 5.
